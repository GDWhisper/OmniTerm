## 1. 环境准备

### 1.1 系统依赖

| 依赖 | 最低版本 | 用途 |
|------|---------|------|
| Rust | 1.87+ | 后端编译 |
| Node.js | 22+ | 前端构建 |
| pnpm | 10+ | 前端包管理 |
| tmux | 3.3+ | 终端会话管理 |
| SQLite | 3.35+ | 数据存储 |

### 1.2 启动开发环境

**一键启动（推荐）：**

```bash
cd /home/pax/coding/OmniTerm

./dev.sh start     # 启动后端 + 前端
./dev.sh stop      # 停止所有服务
./dev.sh restart   # 重启
./dev.sh status    # 查看运行状态
./dev.sh logs      # 实时日志（Ctrl+C 退出）
./dev.sh logs be   # 仅后端日志
./dev.sh logs fe   # 仅前端日志
```

启动成功后输出：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  后端 API:  http://localhost:9777
  前端 UI:   http://localhost:9778
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> 后端仅监听 127.0.0.1（通过 Vite proxy 访问），前端监听 0.0.0.0（局域网可访问）。

**手动启动：**

```bash
# 终端 1：后端
cd /home/pax/coding/OmniTerm
. "$HOME/.cargo/env"
cargo run
# → Listening on 0.0.0.0:9777

# 终端 2：前端
cd frontend
pnpm dev
# → Vite dev server on http://localhost:9778 (proxies /api → :9777)
```

### 1.3 验证服务

```bash
curl http://localhost:9777/api/v1/health
# 期望：{"status":"ok"}
```

## 2. 首次启动

### 2.1 设置管理员密码

1. 打开浏览器访问 `http://localhost:9778`
2. 系统检测到无管理员账号，显示密码设置界面
3. 输入**用户名**（预填默认值 `admin`，可改为自定义名）与密码并提交
4. 自动登录进入主界面

**验证点：**
- [ ] 密码设置成功后自动登录
- [ ] 密码为空时提示错误（用户名留空按默认 `admin` 处理）
- [ ] 刷新页面后仍保持登录状态
- [ ] 用户名规则：1–32 字符、不含控制字符（详见 §20.1）

- [ ] 空名称被拒绝
- [ ] 不存在的路径被拒绝（后端校验）

### 3.2 切换工作区

- 点击工作区名称展开/折叠
- 选中的工作区高亮显示
- 文件管理器自动加载该工作区根目录

**验证点：**
- [ ] 点击切换展开状态
- [ ] 文件管理器内容随工作区切换更新
- [ ] 终端区域不受影响

（当前 UI 未暴露删除按钮，通过 API 测试）


### 3.4 项目路径失效检测与修复（2026-08-08）

项目真实目录被移动/改名/删除后，Sidebar 应标记失效并提供重新定位入口。

**验证点：**
- [ ] 正常项目路径无任何失效标记
- [ ] `mv` 项目目录到别处后，切走再切回浏览器标签页（触发 `visibilitychange` 刷新），项目行路径**变红**并显示 **⚠ 修复按钮**，tooltip 提示「项目路径不存在」
- [ ] 点击 ⚠ 打开「项目路径失效」修复对话框，显示原失效路径
- [ ] 浏览/输入新路径后点「更新路径」，对话框关闭、项目恢复，路径不再标红
- [ ] 修复后在新项目路径下新建会话，终端 cwd 为新的项目目录（不再静默回退到 HOME）
- [ ] 点击失效项目下 worktree 的既有修复流程（`handleWorkspaceClick`）不回归

### 3.5 删除 Worktree 时的分支处理（2026-08-10）

`git worktree remove` 不删分支 ref，所以删除确认框提供 opt-in 的「同时删除分支」。

1. 在某项目下创建 worktree（分支名 `wt-test`）
2. 点该 worktree 行的删除按钮

**验证点：**
- [ ] 确认框里「同时删除分支「wt-test」」复选框**默认未勾选**，下方有未合并提交会丢失的提示
- [ ] 不勾选删除 → 目录消失，再开「创建 Worktree」的基准分支下拉里 **`wt-test` 仍在**（预期行为）
- [ ] 勾选删除 → toast 提示「worktree 及分支已删除」，基准分支下拉里 `wt-test` **消失**，且可再用同名 `wt-test` 重新创建 worktree（不再报「分支已存在」）
- [ ] 当前正在使用（活跃）的 worktree 被删除时，左栏选中态清空，不留失效面板

## 4. 终端会话

### 4.1 创建会话

1. 展开一个工作区
2. 点击 Sessions 旁的 **+** 按钮
3. 可选输入会话名称
4. 确认

**验证点：**
- [ ] 会话出现在工作区下方
- [ ] 会话前有绿色圆点指示器
- [ ] 终端面板自动切换到新会话（无需手动点击列表项）
- [ ] 无名称时显示 tmux 自动生成的名称

### 4.2 连接终端

1. 点击一个会话
2. 终端区域建立 WebSocket 连接
3. 显示 `[attached to session-name]` 绿色提示
4. 出现 shell 提示符

**验证点：**
- [ ] 连接成功显示绿色提示
- [ ] 桌面端点击会话后焦点已在终端上，无需再点一下即可键入
- [ ] 移动端点击会话不自动弹出软键盘（焦点不自动进入终端）
- [ ] 可以正常输入命令（如 `ls`, `pwd`）
- [ ] 输出实时显示，无明显延迟
- [ ] 终端窗口大小自动适配面板
- [ ] 拖拽调整面板宽度后终端自动重新适配

**验证点：**
- [ ] 命令输出正确
- [ ] 交互式程序（vim/htop）正常工作
- [ ] 颜色输出正确渲染
- [ ] 长输出可滚动查看
- [ ] Ctrl+C 中断正常工作

- [ ] 显示 `[disconnected]` 红色提示

### 4.5a 终端自动重连（聚焦页面才重连，2026-09-14）

> 前置：设置里 tmux 失焦/空闲断连滑块保持默认（10/15 分钟）。自动重连只发生在页面可见时；页面隐藏期间零尝试，回来（切回标签 / 窗口聚焦 / 任意鼠标键盘活动）立即重连并重置退避节奏。

**A. 意外断开自愈（后端重启）**
1. 保持页面在前台，重启 dev 后端（`./dev.sh restart`）
2. 不做任何操作，观察终端

**验证点：**
- [ ] 断开后遮罩出现且带「正在自动重连…」提示
- [ ] 约 1s 内自动重连成功，遮罩自行消失，无需点击
- [ ] 后端持续不可用时：遮罩保留、提示不消失，退避间隔逐步拉长（≥30s 一次）；恢复后端后自动接上

**B. 失焦/空闲拆除后回归自愈**
1. 切到其他窗口（或最小化标签）超过设置的失焦断连时长（默认 10 分钟）
2. 切回来，观察终端；空闲断连（默认 15 分钟无输入）则在页面上动一下鼠标

**验证点：**
- [ ] 回来后无需点击「重连」，终端自动重建并接上（画面经补屏重放恢复）
- [ ] 桌面端自动重建不抢焦点：正在聊天面板输入时焦点不被终端拉走
- [ ] 手动「重连」按钮仍然可用且立即生效；重连期间遮罩按钮上方有「正在自动重连…」提示

### 4.6 pty 帧渲染视觉确认（cell_frame / runs 行编码）

> **适用范围**：pty 引擎会话（tmux 引擎是 raw 直通，不走服务端 grid 编码）。
> 可结构化断言的部分已由 `node scripts/pty-frame-regression.mjs`（17 项）覆盖，
> 本节只做**浏览器内的视觉确认** —— 字体、配色、光标形状、emoji 字形、宽字符
> 对齐、TUI 刷屏观感。改动 `src/engine/pty/` 的帧编码或 `useCellFrame.ts` 后
> 需过一遍（`docs/dev/plans/archive/2026-08-28-pty-frame-rle.md` §6）。
>
> 前置：按 §1.2 起服务，创建一个 **pty** 引擎会话（默认即是 pty），浏览器打开
> 前端（端口见 `.env.local` 的 `FRONTEND_PORT`）。下列命令整段粘进终端执行。

**V1 基础文本与颜色**

```bash
echo "Hello OmniTerm"
ls --color=always -la /usr/bin | head -30
printf '\x1b[1;31mBOLD RED\x1b[0m \x1b[4;34munderline blue\x1b[0m normal\n'
```

**验证点**
- [ ] 颜色、粗体、下划线范围准确，样式不越过行尾
- [ ] 序列结束后样式复位，后续提示符不是彩色

**V2 CJK / 全角对齐（宽字符占 2 列）**

```bash
printf '|中文|abc|\n'
printf '|abc|中文|\n'
printf '|12345|\n'
for i in $(seq 1 40); do echo "中文测试 $i ターミナル 滚动压测"; done
```

**验证点**
- [ ] 前两行的三根竖线**完全对齐**（中文按 2 列、ASCII 按 1 列）
- [ ] 第三行竖线比前两行靠前 2 列（符合宽度计算，非 bug）
- [ ] 全角/半角混排行没有字符重叠或半个字符

**V3 emoji（肤色修饰符 / ZWJ / 变体选择符）**

```bash
printf '👍 👍🏽 👨‍👩‍👧‍👦 ❤ ❤️ 🇨🇳 😀\n'
```

**验证点**
- [ ] `👍🏽` 是有肤色的竖拇指，不是「黄拇指 + 焦糖色方块」
- [ ] `❤️`（U+2764 + VS16）显示成彩色红心，不是黑白心形
- [ ] `👨‍👩‍👧‍👦` 合成一个家庭字形，不裂成四个头像
- [ ] 国旗与其余 emoji 等宽对齐

**V4 组合音标（零宽字符，`E-10` 专项）**

```bash
printf 'cafe\xcc\x81 na\xcc\x88ive A\xcc\x8a\n'
printf 'e\xcc\x81\xcc\x80\xcc\x81\n'
printf 'e\xcc\x81\ne\xcc\x81\n'
```

**验证点**
- [ ] `café` 的 é 是「e 上加锐音」的单个字形，不是 `e` 后跟一个孤立符号
- [ ] `ë`、`Å` 同理；多重组合符叠加在一格内，不占额外列
- [ ] 后两行渲染完全一致（组合符未被吞、未漂移）

**V5 行尾空格与背景色（RLE 不得截断尾部）**

```bash
printf '\x1b[41m%-40s\x1b[0m|END\n' 'selected'
printf 'AAA   \x1b[42m   \x1b[0mBBB\n'
```

**验证点**
- [ ] 第一行红底一直铺到第 40 列，`|END` 紧跟其后、没有被吞掉空格
- [ ] 第二行中段 3 个空格是绿底且可见，`BBB` 位置正确

**V6 快速输出不丢行 / 不撕裂**

```bash
seq 1 20000      # 输出中按 Ctrl+C 中断
```

**验证点**
- [ ] 数字连续无跳号、无整行错位
- [ ] 中断后画面停在某一帧，没有半行/错位残留

```bash
top              # 观察 2 秒后按 q 退出
```

- [ ] 退出后主屏完整恢复，**无 alt 屏内容残留**
- [ ] alt-screen 内滚轮交回 xterm（不触发后端历史窗口接管）

**V8 历史窗口滚动（后端视口接管）**

```bash
for i in $(seq 1 1500); do echo "中文测试 $i ターミナル 滚动压测"; done
# 然后滚轮 / PageUp 向上滚，再滚回底部
```

**验证点**
- [ ] 滚动跟手，无长时间空窗（帧已降到 4.8 KB）
- [ ] 历史窗口内容连续，CJK 行在历史窗口里同样对齐（同 V2 判据）
- [ ] 滚回底部后恢复实时输出

**V9 断线重连与多连接（`E-11` 专项）**

1. 会话里跑 `seq 1 500`，结束后**刷新浏览器** → 重新点该会话
2. 会话**空闲 10 秒**（不输入任何内容）后刷新 → 重新点该会话
3. 再开一个标签页打开**同一个** pty 会话，一边跑 `top`，一边观察另一个标签页

**验证点**
- [ ] 刷新重连后画面与刷新前一致（补屏正确）
- [ ] **空闲会话重连后立即出画面**（旧缺陷：ticker 懒初始化 + `select!` 挂起导致
      连接静默停在 raw 模式，画面空白且滚轮无响应）
- [ ] 两个标签页同时 attach 同一会话，两侧画面都正常刷新

**V10 升级后的旧资源缓存（已知取舍）**

cell_frame 只有 runs 一种行编码（旧的 `cells` 格式与 `hello.row_encoding` 协商
已移除）。前后端由同一产物发布，正常升级不会错配；仅当浏览器缓存住旧版前端
资源时，旧前端读不到 `runs` 而显示空行。

**验证点**
- [ ] 升级后若终端显示空白/空行 → 强制刷新（Ctrl+Shift+R）后恢复正常

**V11 上翻历史时新输出不冻结（绝对锚定 + 回底提示条）**

1. 跑 `top`，**在 top 运行期间**用滚轮向上翻几行（top 不进 alt-screen，滚轮会被接管）
2. 保持上翻状态不动，观察 10 秒
3. 敲 `q` 退出 top
4. 跑 `for i in $(seq 1 1500); do echo "中文测试 $i ターミナル 滚动压测"; done`，再上翻查看

**验证点**
- [ ] 上翻后右下角出现「↓ 下方有新输出」提示条
- [ ] 上翻期间窗口内容随输出推进（旧缺陷：永久停在上翻那一刻的快照，后续
      输出完全不可见，只有切换会话才恢复）
- [ ] 敲 `q`（任意按键）立即回到底部，提示条消失
- [ ] 点击提示条同样回底
- [ ] 空闲会话（无输出）上翻时不出现提示条、无额外请求
- [ ] 压测后再上翻，序号连续无跳号

**V12 周期性内容锚定（有状态锚，2026-09-12）**

> 与 V11 的差别：V11 压测行内容全唯一，指纹/位置机制都能过；本用例让锚点行

### 12.2 Prompt 与流式渲染

| 步骤 | 预期 |
|------|------|

### 12.4 上次输入卡片（跳转聚焦，2026-09-12）

> 消息区顶部居中的单行悬浮卡片（pixel-float 浮层，不占布局）：展示最近一次已送达的用户输入，点击跳回那个气泡。显隐按气泡相对视口位置三分：视口内、沉到视口下方（上翻进了更早历史）都收起，仅气泡升出视口顶缘（正在阅读其后的回复）时显示。

| 步骤 | 预期 |
|------|------|
| 会话已有至少一条已送达 user 消息 | 消息区顶部居中悬浮单行卡片，仅显示消息正文（无「上次输入」标签，多行压平空白） |
| 长消息 | 卡片最宽约占消息区 60%（移动端 88%），超出单行 ellipsis 截断；hover 出原生 tooltip 显示完整内容 |
| 目标气泡在视口内（用户正看着它） | 卡片收起 |
| 向下滚过这条消息、正在阅读其后的回复（气泡升出视口顶缘） | 卡片显示——作为「你最后问了什么」的参照 |
| 上翻越过这条消息、浏览更早历史（气泡沉到视口下方） | 卡片收起——多轮会话翻旧历史时不常驻 |
| 点击卡片 | 消息列表向上滚回该气泡、恰好落在卡片下方不被遮挡处，气泡出现 accent 描边 + ring 闪烁约 1.5s 后消退；随后气泡已在视口内，卡片自动收起 |
| 闪烁未消时滚开再点一次 | 闪烁动画重新播放（不是只滚动不动） |
| 最近一次输入是断连留痕气泡（undelivered，虚线框「未送达」） | 卡片显示的是再往前一条**已送达**的 user 消息；点击不跳到留痕气泡 |
| 刚发送新消息（auto-stick 在底部） | 新消息通常在视口内 → 不出现；回复流式变长把它顶出视口顶后出现 |
| 纯附件消息（无正文） | 卡片显示 `[附件]` 占位 |
| 会话尚无任何 user 消息（新会话） | 不渲染卡片 |
| hover / 按压卡片 | hover 底色 `--bg-elevated` → `--bg-surface`；按压 2px 硬阴影位移（§6 约定） |
| 极短会话内容不足一屏 | 气泡始终在视口内，卡片不出现 |
| 用户滑动消息区（滚轮 / 触摸拖动）期间 | 卡片淡出至约 35% 不透明度（0.15s ease-out）——不挡住从它下面滑过的正文 |
| 停止滑动约 0.2s 后 | 卡片恢复不透明，可读可点 |
| agent 流式输出把气泡顶出视口（用户没动手滑） | 卡片**不**淡出——自动贴底钉回也是 scroll 事件，但那是内容在动、用户在读 |

### 12.5 「回到底部」按钮（离底即显，2026-09-13）

> 消息区底缘居中的悬浮按钮（浮在输入区之上、不占布局）：离开底部即显示，滚回底部后消失——不要求尾部有新内容到达，流式输出与会话结束/空闲回看历史时都可用。

| 步骤 | 预期 |
|------|------|
| 贴底（自动跟随中，含内容不足一屏） | 不显示按钮 |
| 上翻离开底部（无论会话是否仍在流式输出） | 立即显示「↓ 回到底部」按钮，末条是否有新内容不影响显隐 |
| 会话结束/空闲（无任何新输出）时上翻 | 同样显示按钮 |
| 点击按钮 | 立即滚回底部并恢复自动跟随，按钮消失；此后新输出继续贴底跟随 |
| 手动滚回底部 | 按钮消失，流式输出继续贴底跟随 |
| 用户滑动消息区（滚轮 / 触摸拖动）期间 | 按钮淡出至约 35% 不透明度（与「上次输入」卡片同一档、同一 token，0.15s ease-out）——不挡住从它下面滑过的正文 |
| 停止滑动约 0.2s 后 | 按钮恢复不透明，可读可点 |
| agent 流式输出把内容顶长（用户没动手滑） | 按钮**不**淡出——自动贴底钉回也是 scroll 事件，但那是内容在动、用户在读 |
| 与「上次输入」卡片同时在场时滑动（离底但气泡已升出顶缘） | 两个浮层同步淡出、同步恢复 |

### 12.6 贴底态的维持（布局变化不丢追底，2026-09-21 / 2026-09-23）

> 贴底态（`autoStick`）由「滚动位置」单一事实来源推导，但把底缘推远的**不只是滚动**：容器尺寸变化（键盘收放、todo 看板/权限条/输入区长高）与滚动内容长高（思考/重放指示、终端事件）都不改消息、也不保证发 scroll 事件。跟随中这些变化必须重新钉底——否则视口静默停在半空，且因 `autoStick` 仍为 true 连「回到底部」按钮都不显示（用户只能手滚，手滚停在离底 >24px 就永久解除跟随）。另一类同源症状：非 React 来源的布局变化（图片解码完成、字体替换、定时器直写 DOM）发生在「钉底写入」与「该写入触发的 scroll 事件派发」之间时，事件会读到 ≥ 阈值的间距——解除判定若只看间距，贴底态会在**零用户操作**下被永久解除（此后整轮流式都不跟随）。

| 步骤 | 预期 |
|------|------|
| 移动端贴底跟随中切到 sidebar（会话列表）再切回 | 仍在底部、无「回到底部」按钮；期间 agent 有输出也不掉底缘 |
| 移动端贴底跟随中切到 files 面板再切回 | 同上 |
| 贴底跟随中在输入框聚焦 / 收起键盘（移动端） | 最新一行始终可见，消息区随键盘收放重钉底缘 |
| 贴底跟随中 agent 出现 todo 看板 / 权限条 / 队列 chip（消息区被压矮） | 仍贴底，不出现回底按钮 |
| 贴底跟随中流式输出里插入工具调用 / 终端事件行 | 仍贴底 |
| 贴底跟随中，上一条用户消息里的图片附件解码完成（内容瞬间长高） | 仍贴底、无「回到底部」按钮，后续输出继续跟随 |
| 贴底跟随中全程不做任何滚动，直到本轮输出结束 | 全程贴底、回底按钮始终不出现（含工具调用/思考块插入） |
| 已上翻读历史（按钮已显示）时切到 sidebar/files 再切回、或键盘收放 | 阅读位置不动、按钮仍在（重钉不干预非跟随态） |

### 12.7 agent 侧失败可见化（非正常 stopReason + 空 turn 留痕，2026-09-26 / 2026-10-09 补）

> 背景：协议在 `session/prompt` 正常返回（非 JSON-RPC error）时也可能表示失败——`end_turn` 之外的终态（本例 agent 侧工具批次异常）只存在于 agent 自己的日志。修复前 OmniTerm 把该 turn 定稿为 complete，聊天流里没有任何失败痕迹。现按协议白名单判定并在聊天流落一条 system 消息。构造方式见协议参考 §6.8：heredoc 里写 `${<上文标识符>}` 即可稳定复现（**必须用 `<<'EOF'` 引号分隔符**——真 shell 合法而 codebuddy 的派发前解析器会误判，从而稳定触发）。2026-10-09 补：另一形态是**白名单值本身被用来掩盖失败**——实现把对端错误折成 `end_turn` 且一个内容帧都不发，此时判据必须加「本轮有无可见产出」，见 §6.8 的 pi-acp 实测行与下方用例。

| 步骤 | 预期 |
|------|------|
| ACP 会话发一条会触发失败的 prompt：`cat <<'EOF' > /tmp/x.txt` 换行 `${createHmac}` 再 `EOF` | 回合结束（不再流式），左侧通知出现**错误**态（而非完成态） |
| 同一会话查看聊天流末尾 | 出现一条 `[…]` 样式的 system 消息，文案含 `stopReason=refusal`，位置在正文之后 |
| 该会话**刷新页面** | 失败提示仍在（后端已落库，hydrate 还原）——这是「离线/刷新仍可见」的核心用例 |
| 换设备/换标签打开同一会话 | 同上，提示可见 |
| 正常完成一个 prompt（无失败） | **不出现**任何 system 提示、通知走完成态（防误报回归） |
| 让 agent 撞到 token 上限而结束（长会话 / 缩小上下文后追问） | 视为**正常**结束：无失败提示、无错误通知（白名单含 `max_tokens`） |
| 造一个「协议说成功、实际零产出」的空气泡（2026-10-09 实测形态）：让 agent 的模型提供方拒供后发一句 prompt——例如把 pi 的 stepfun 账号留在未实名状态（403 `real_name_required`），pi-acp 会把它折成 `end_turn` 返回 | 聊天流出现一条含「这一轮没有任何输出（stopReason=end_turn）」的 system 消息，通知走**错误**态；该轮气泡是空的但提示必须在。**对照**：同一会话正常完成一条带正文/工具调用的 prompt 时不得出现这条提示（防误报） |
| 手动取消进行中的 prompt（取消按钮） | 出现「已取消」文案（`stopReason=cancelled`），但**不走错误态**、不响错误提示音 |
| 流式输出中排队一条消息 → 点队列 chip 的 ▶「立即发送」（2026-10-06） | 当前 turn 被打断，聊天流**只有一条**「已取消」提示；被排队的那条消息随后正常得到 agent 回复——不得出现第二条「已取消」而那条消息没人理（agent 侧 cancel 粘滞窗口回归，见 `docs/dev/debug-patterns/platform-protocol.md` 模式 13） |
| 失败提示出现后再次发送 prompt | 发送即自动恢复（若进程已被回收），且不会重复出现上一条失败提示 |

> 已知残留（不影响本组用例）：WS 离线期间发生的失败提示只有**整页刷新**后才可见——仅重连（不刷新）时不会重新拉取历史，当前标签页内看不到。同一条限制也影响权限超时告知。

### 12.8 气泡内 markdown 排版（段落/标题/列表不挤一团，2026-10-04）

> 背景：Tailwind Preflight 全局 reset 抹掉 UA 默认排版，react-markdown 产出的段落/标题/列表在气泡里曾零间距、无列表符号。修复与规格见 ui-style-guide §7.6。以下用例覆盖定稿渲染；流式期间的 pre-wrap 纯文本降级不在此列。

| 步骤 | 预期 |
|------|------|
| ACP 会话让 agent 输出一段含 `##`/`###` 标题、`-` 列表、`>` 引用、`---` 分隔线的长回答 | 定稿后：段落间有间距；标题加粗且比正文大一级；列表项带符号（`•`/数字）并整体缩进；引用块左侧有竖线；分隔线可见 |
| 同一气泡内**首行**与**末行** | 紧贴气泡 padding（无双重留白）——首/尾子元素外边距归零 |
| 深色 / 亮色主题各看一遍 | 排版一致；代码块仍为 oneDark 恒定深底、气泡圆角不变（聊天历史值） |
| 流式中（agent 还在输出） | 仍是 pre-wrap 纯文本（不全量解析），回合定稿瞬间一次性变为排版后的 markdown |

## 13. ACP 配置偏好持久化（2026-08-04）

> 前置：§11 创建过可用 agent；后端已应用 migration `20260804_acp_config_preferences.sql`。
> 底部配置栏（Mode/Model/Thinking/Config 选择器）只在 agent 下发 `config_options` 后可见，以下用例以可见为前提。

### 13.1 新建会话继承 agent 全局偏好

| 步骤 | 预期 |
|------|------|
| 在会话 A 的底部配置栏修改 Model（如从默认切到另一值） | 配置生效，配置栏显示新值 |
| 新建同一 agent 的会话 B | B 的底部配置自动显示会话 A 设置的 Model 值（agent 级偏好继承） |
| 在 B 中改回默认值 | B 生效；下次再建同 agent 会话 C 时按 B 的最终值继承 |

### 13.2 会话级覆盖优先

| 步骤 | 预期 |
|------|------|
| 在会话 A 设置 Model=X（此时 agent 全局偏好也是 X） | 两个表记录一致 |
| 在会话 A 把 Model 改成 Y | 仅会话 A 变 Y；agent 全局偏好仍 X |
| 新建会话 B | B 显示 X（agent 级） |
| 手动释放会话 A（release）后重新恢复（load_session） | A 显示 Y（会话级覆盖） |

### 13.3 进程生命周期内配置记忆

| 步骤 | 预期 |
|------|------|
| 修改配置后刷新浏览器（进程存活） | 刷新后配置栏仍显示上次值（`initial_config_notification` 回推缓存） |
| 手动 release 会话 → 重新进入会话 → 点「恢复会话」 | 重放期间配置栏短暂显示 agent 默认值，`ReplayEnd` 后切换为恢复值 |

### 13.4 删除清理

| 步骤 | 预期 |
|------|------|
| 删除一个 ACP 会话 | `session_config_options` 对应行被清理（或 FK 级联） |
| 删除一个项目 | 项目下全部会话的 `session_config_options` 被清理 |
| 删除一个 agent（无会话引用时） | `agent_config_preferences` 对应行被清理 |

### 13.5 边界与降级

| 步骤 | 预期 |
|------|------|
| agent 侧移除某配置项后恢复会话 | 该项被跳过、不报错，其余项正常恢复 |
| agent 不返回 `config_options`（如 opencode 部分路径） | restore 自动跳过（缓存空无法过滤），会话正常建立，配置栏可能为空（已知能力边界） |
| 恢复期间 agent 响应慢/失败 | 单项目 warn 跳过，10s 超时兜底，不阻塞会话建立/恢复 |

### 13.6 发送即自动恢复（进程已释放）

| 步骤 | 预期 |
|------|------|
| ACP 会话空闲 5 分钟被 reaper 自动回收（或手动 release）后，直接输入并发送消息 | 无需点「恢复会话」，后端自动 spawn agent + 历史重放，稍后 agent 正常回复；期间不出现 Internal error |
| 恢复过程中「已释放」指示（DEAD badge / 恢复按钮） | 保持稳定不闪断（3s 轮询不覆盖），发送后恢复成功自动转为 LIVE |

| 释放后刷新浏览器（WS 重连，进程不在 supervisor） | 会话显示「已释放」而非「已结束」，输入可用；发送消息自动恢复，不再强制先点恢复 |

### 13.7 已结束会话的配置快照置灰展示（2026-09-13）

> 前置：后端已应用 migration `20260913_add_config_options_snapshot.sql`；agent 会下发 `config_options`（配置栏可见）。

## 19. tmux server 假死检测 + 重建（2026-09-22）

> ⚠ **安全护栏**：任何制造/模拟聋态的实验**只允许在私有 socket 上做**（如 `tmux -L omniterm_test_$$`），**禁止拿默认 socket（`/tmp/tmux-<uid>/default`）做实验**——误动默认 socket 上的真实 tmux server 会一次性丢掉全部 tmux 会话（实现期已有一次同类疑似误杀事故，见计划实施勘误 ㉔）。仅验证告警 UI 路径时用**前端 mock** 即可，不碰真实 tmux。

**A. 告警横幅 + 重建按钮（前端 mock，推荐）**

把 `GET /api/v1/tmux/health` mock 为 `{"state":"deaf","consecutive_deaf":3,"last_deaf_at":…,"orphan_count":0,"orphan_warn_threshold":5,"probe_interval_secs":30}`（fixture 可参照 `TmuxHealthAlert.test.tsx`）。

**验证点：**
- [ ] 页面顶部出现全局告警横幅（⚠ + 「检测到 tmux server 假死（聋 server）」）+「重建 tmux server」按钮，桌面/移动/侧栏折叠态均可见

- [ ] `consecutive_deaf` 为 1 或 2 时**不告警**——连续 3 次 Deaf 才告警（防单次探测抖动误报）
- [ ] `state=other` 只显示轻量提示、无重建按钮；`healthy` / `no_server` 完全静默

**B. 点重建：成功路径（mock `POST /tmux/rebuild` 200 `{ok:true,…}`）**

1. 点击「重建 tmux server」

**验证点：**
- [ ] 按钮变「重建中…」并禁用（防双击连发）
- [ ] 成功 toast「tmux server 已重建」；health 立即刷新（不等下一轮 10s 轮询），mock 恢复 healthy 后横幅自动消失

**C. 409 / 500 分支文案**

| mock 返回 | 预期 |
|------|------|
| 409 `{"error":"not_deaf"}` | info toast「tmux server 已恢复，无需重建」+ 刷新 health，**不自动重试**（下一发可能命中健康新 server） |
| 409 `{"error":"heal_in_progress"}` | info toast「重建进行中」，不重试轰炸 |
| 500（含其它网络失败） | error toast「重建 tmux server 失败: <error 串>」 |

## 20. 账号用户名与本地免密访问（2026-09-27）

> 需求：① 登录从「仅密码」升级为「用户名 + 密码」（单账号，用户名可自定义）；② 设置面板新增「本地访问校验」开关，关闭后本机（`127.0.0.1` / `localhost`）访问免密，**远程（浏览器）访问仍需密码**——非浏览器客户端经「透传 Host 的中间层」的穿透属已知边界，见下方边界表。
> 设计与威胁模型（四条判据、穿透路径分析）：`docs/dev/plans/2026-09-27-auth-username-local-bypass.md`。

### 20.1 用户名（首次设置 / 登录 / 修改）

1. 首次访问（无账号）→ 密码设置页：用户名字段预填 `admin`，可改成自定义名
2. 输入密码提交 → 自动登录
3. 登出后用**自定义用户名 + 密码**登录；用 `admin` + 同密码登录应失败（401）
4. 设置 → 密码验证区块 → 「修改用户名」：输入当前密码 + 新用户名 → 提交

**验证点：**
- [ ] 自定义用户名可登录；旧用户名（含缺省 `admin`）登录 401
- [ ] 改用户名成功后回到登录页（全部会话立即失效），新用户名可登录
- [ ] 改用户名时密码错误 → 401；新用户名空 / 超 32 字符 / 含换行 → 校验错误
- [ ] 老库升级（已有密码、无用户名列）：migration 自动填 `admin`；登录不传用户名按 `admin` 比对仍可登录（老脚本兼容）

### 20.2 本地访问校验开关

1. 设置 → 密码验证开启后 → 出现「本地访问校验」开关（默认**开启** = 本机也要求登录）
2. 关闭开关 → 本机浏览器新开标签/刷新 → 免密直接进入
3. 用**浏览器**从局域网/远程设备（`http://<LAN-IP>:端口` 或域名）访问 → **仍要求密码**（非浏览器客户端见边界表）

**验证点：**
- [ ] 开关默认开启：本机访问也要求登录（不静默弱化既有部署的姿态）
- [ ] 关闭后本机免密（无 cookie）：`curl -H 'Host: 127.0.0.1:9777' http://127.0.0.1:9777/api/v1/system/info` → 200
- [ ] 远程/穿透形态仍 401：`Host: <LAN-IP>`、域名、`Host: localhost.evil.com`、带 `X-Forwarded-For` / `X-Real-IP` / `Forwarded`、`Origin: https://evil.com`、`Origin: null`
- [ ] 本机在设置里**重新打开**开关 → 本机下一请求立即 401（需重新登录）
- [ ] 免密进入时 `GET /api/v1/auth/check` 返回 `local_bypass: true`
- [ ] WS 链路：本机免密可完成握手（101）；远程 Host 无 cookie 401

**边界与已知限制（务必阅读）：**

| 情形 | 行为 | 说明 |
|---|---|---|
| 同机反代 + Host 被改写为**回环地址** + 未注入任何转发头 | **远程流量可能命中免密** | 应用层无法区分「本机浏览器直连」与「同机反代转发」；缓解：让反代注入 `X-Forwarded-For`（标准配置），或不要在反代部署上关闭本开关 |
| 同机代理**原样透传**客户端 Host + 未注入转发头（Vite dev / nginx `Host $http_host` / 裸 TCP 转发 / `ssh -R`） | **能自定 Host 的客户端（curl/脚本）可伪造回环 Host 命中免密**；浏览器不受影响 | `Host` 是客户端可控头。2026-09-28 实测：`curl -H 'Host: 127.0.0.1:<后端端口>' http://<LAN-IP>:<前端端口>/api/v1/...` → 200（浏览器经 Vite 从 LAN 访问则 401，见下行）。dev 下后端仅监听 127.0.0.1，Vite 是唯一 LAN 入口。Caddy 默认注入 `X-Forwarded-*` → 不被穿透 |
| SSH 隧道（`ssh -L`）后浏览器访问 localhost | 命中免密 | 隧道由用户本人建立，语义上属本机用户（接受） |
| 经 Vite dev（:9778）从**局域网**用**浏览器**访问 | **不会**免密 | 浏览器发出的 Host 是 LAN IP（非回环字面量）；非浏览器客户端见上一行 |
| 代理子域形态（`{port}.<domain>`） | 永不命中免密 | Host 是域名，按设计（记录为边界） |
| 忘记密码 + 本地免密 | 改密码/改用户名仍要求当前密码 | 出路：`--reset-auth` 清空账号后重设；不提供免密改密路径 |
| 无 `Origin` 的顶层导航 / curl | 不触发 Origin 条件 | 能连回环者本就可访问本机服务（接受为边界） |
| 畸形 `Host`/`Origin`（如 `[::1]@evil.com`） | 按解析失败处理（非回环 → 需登录） | `strip_port` 的方括号串只校验 `]` 之后为 `:数字`（2026-09-28 收紧），其余原样返回由调用方判定 |
| `--host ::` 双栈监听 + v4 客户端（对端 `::ffff:127.0.0.1`） | 本地免密不生效（需登录） | std `IpAddr::is_loopback` 仅认 `::1`，刻意 fail-closed；`--host 0.0.0.0`/`127.0.0.1` 不受影响 |
| 本地免密命中 = 信任本机全部进程/账号 | 免密进入者（含本机任意进程）可无凭据 `POST /auth/settings {auth_enabled:false}` 关闭总开关 | 单人自用机器上不构成新能力；多用户 / 受限权限机器需自行评估 |

- [ ] **不点任何按钮**，断连期间的消息自动出现（旧行为：停在旧对话，须手动「恢复会话」或 F5）
- [ ] 消息不重复：每轮 user / assistant 各一条，无同文本双气泡；无多余「未送达」留痕
- [ ] 进行中的 turn 正常续接：思考指示器不假死，`turn_snapshot` 后流式继续，耗时数字出现
- [ ] 若聚焦时正在贴底，视口钉在最新一条；若聚焦前停在中途读历史，聚焦补拉**不抢**滚动位置

### 21.2 边界

| 情形 | 预期 |
|---|---|
| 会话从未断连（短时间切走再回，<125s） | 不发补拉请求（省流量），live 帧持续更新，无感 |
| 聚焦时后端不可达（断网/后端挂了） | 不弹错、不打扰；恢复后下次聚焦自动补拉 |
| 补拉期间用户正在手动「恢复会话」（重放中） | 不等重放，重放结束后自然最新 |
| 断连期间 turn 仍在跑 | 该轮由 `turn_snapshot` 续接（半截消息被 DB 完整行按前缀补齐），不出现两条 assistant |
| 切到别的 ACP 会话再切回 | 切回即补拉一次（该会话断连标记仍在页面生命周期内有效） |
| **移动端切后台（切 app / 锁屏）再回来** | 不刷新即最新：回来即自动补拉一次（移动端离开 ≥3s 兜底），bfcache 恢复同样兜底 |
| **断开发生在页面可见时**（含移动端恢复后补派的迟到 onclose） | 不等用户再失焦：标记就位即补拉一次 |

### 21.3 移动端切后台回来（2026-10-04 勘误）

> 前置：手机浏览器（iOS Safari / Android Chrome）打开 OmniTerm 与一个 ACP 会话。
> 背景：桌面链路依赖「`ws.onclose` 置断连标记」；移动端切后台会把页面冻结，断连信号产生于冻结期内——WebKit 类不补派 onclose、Chromium 类恢复到可见后才补派，桌面那条链在移动端恒失配（旧行为：必须手动刷新）。现按「真实离开过即兜底」补拉，与标记链并存。

1. ACP 会话里让 agent 跑一轮较长任务
2. 切到别的 app 或锁屏，停留数秒以上（不苛求 125s——兜底按「真实离开」计）
3. 切回浏览器标签

**验证点：**
- [ ] **不点刷新**，离开期间 agent 落库的新消息自动出现
- [ ] 消息不重复：无同文本双气泡；user 回显不裂成两条
- [ ] 回来时若在贴底，视口钉在最新一条；若离开前停在中途读历史，回来**不抢**滚动位置
- [ ] 桌面端不回归：短切走再回（无断连）不发补拉请求

### 21.4 断连吞掉 prompt_done 后补拉：回声与半截回复不双显（2026-10-07 勘误）

> 前置：一个 ACP 会话与一个耗时超过数秒的 agent 任务。
> 背景：turn 进行中 WS 断开（服务端重置 / 承载网 RST）时，`prompt_done` 连同 `row_id` 被广播丢弃——store 停在 [user echo(无 dbId), assistant 半截(无 dbId)]；重连后聚焦补拉把 DB 页 `[user 行, assistant 行]` 合进来。旧实现对账只认 store **尾部一条**，而 echo 后面永远跟着 assistant，尾部角色对不上 ⇒ user 行按 createdAt 插成新气泡：用户消息双显示、顺序错乱（正式版 codebuddy_1007-1314 实测）。

1. ACP 会话里发一条消息，让 agent 跑一轮较长任务（含工具调用）
2. 任务**跑完之前**断开网络（关 Wi‑Fi / 飞行模式）数秒再恢复（覆盖 turn 结束落在断连窗口内）
3. 等 agent 在后台跑完该轮，切回 OmniTerm 标签（触发聚焦补拉）

**验证点：**
- [ ] user 消息只有一条（echo 被 DB 行原位替换，不裂成两条）
- [ ] assistant 只有一条且是完整回复（半截被 DB 行按前缀补齐，不出两条 assistant）
- [ ] 顺序为 user → assistant，无插错位置的气泡
- [ ] 刷新页面后与补拉后的展示一致（DB 侧始终只有两条行）

## 23. 删除 ACP 会话时抹掉 agent 侧记录（2026-10-07）

> 前置：一个声明了 `sessionCapabilities.delete` 的 agent（实测 **opencode 2.0.24**、
> **pi-acp 0.0.34** 可用；**codebuddy 未声明**，用作反面用例）。
> 背景：omniterm 删会话原本只杀进程 + 删自己的库，agent 自己那份会话历史永久残留。
> 2026-10-09 更新：无活连接（已释放 / 回收 / 后端重启 / 连接已死）不再提示「先恢复
> 会话」——后端**临时拉起**短命 agent 进程现场探明能力并补发删除；勾选框唯一禁用
> 原因是「agent 已知不支持」。

**主路径（能力支持的 agent）：**

1. 新建一个 ACP 会话（用 opencode），随便聊一句让 agent 侧真的落一条记录
2. 侧栏会话行右键（或悬停）→ 删除，打开二次确认弹窗

**验证点：**

- [ ] 弹窗里出现**红字**勾选框「同时永久删除 agent 侧会话记录」
- [ ] **首次**打开（清掉 `localStorage.omniterm_delete_agent_side`）默认**不勾选**
- [ ] 勾选后确认：会话消失，toast 提示「agent 侧会话记录已删除」
- [ ] 用 agent 自己的 CLI 或 `session/list` 复核：该 `acp_session_id` 已不在 agent 侧列表里
- [ ] **记忆**：刷新页面 → 再删另一个 ACP 会话 → 勾选框**默认已勾选**（上次的选择被记住）
- [ ] **可记住取消**：取消勾选后确认删除 → 再开一次弹窗 → 默认**不勾选**
- [ ] **未知能力**：删一个本浏览器从未打开过的 ACP 会话 → 勾选框**可勾选**；勾选删除时后端现场拉起短命 agent 探明能力并补发删除（支持删除的 agent 应 toast「已删除」，用 `session/list` 复核该 id 消失）
- [ ] **已释放**：先点「释放进程」再删除（勾选框仍可勾选）→ 后端临时拉起 agent 补删，toast「agent 侧会话记录已删除」；**不得**出现「请先恢复会话再删除」的提示
- [ ] **已归档**：从「已归档」区块删除归档会话并勾选 → 同上（归档会话必然已释放）
- [ ] **不支持**（codebuddy 会话）：勾选框**禁用** + 说明「该 agent 未声明支持删除…需手动清理」，会话照常删除（唯一禁用原因）
- [ ] **批量删除**：选中多个 ACP 会话（混入不支持项）→ 删除 → 勾选框可用性与上面一致；确认后 toast 分别汇总「已删除 N 个 / 未能删除 M 个」
- [ ] 删除**项目**时**不**出现该勾选框（项目级联删除不代发 agent 侧删除）
- [ ] 归档 ACP 会话后，agent 侧记录**仍在**（归档要保留历史供只读查看）
