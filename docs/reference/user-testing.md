## 1. 环境准备

### 1.1 系统依赖

| 依赖 | 最低版本 | 用途 |
|------|---------|------|
| Rust | 1.87+ | 后端编译 |
| Node.js | 22+ | 前端构建 |
| pnpm | 10+ | 前端包管理 |
| tmux | 3.3+ | 终端会话管理 |
| SQLite | 3.35+ | 数据存储 |

### 1.2 启动开发环境

**一键启动（推荐）：**

```bash
cd /home/pax/coding/OmniTerm

./dev.sh start     # 启动后端 + 前端
./dev.sh stop      # 停止所有服务
./dev.sh restart   # 重启
./dev.sh status    # 查看运行状态
./dev.sh logs      # 实时日志（Ctrl+C 退出）
./dev.sh logs be   # 仅后端日志
./dev.sh logs fe   # 仅前端日志
```

启动成功后输出：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  后端 API:  http://localhost:9777
  前端 UI:   http://localhost:9778
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> 后端仅监听 127.0.0.1（通过 Vite proxy 访问），前端监听 0.0.0.0（局域网可访问）。

**手动启动：**

```bash
# 终端 1：后端
cd /home/pax/coding/OmniTerm
. "$HOME/.cargo/env"
cargo run
# → Listening on 0.0.0.0:9777

# 终端 2：前端
cd frontend
pnpm dev
# → Vite dev server on http://localhost:9778 (proxies /api → :9777)
```

### 1.3 验证服务

```bash
curl http://localhost:9777/api/v1/health
# 期望：{"status":"ok"}
```

### 3.4 项目路径失效检测与修复（2026-08-08）

项目真实目录被移动/改名/删除后，Sidebar 应标记失效并提供重新定位入口。

**验证点：**
- [ ] 正常项目路径无任何失效标记
- [ ] `mv` 项目目录到别处后，切走再切回浏览器标签页（触发 `visibilitychange` 刷新），项目行路径**变红**并显示 **⚠ 修复按钮**，tooltip 提示「项目路径不存在」
- [ ] 点击 ⚠ 打开「项目路径失效」修复对话框，显示原失效路径
- [ ] 浏览/输入新路径后点「更新路径」，对话框关闭、项目恢复，路径不再标红
- [ ] 修复后在新项目路径下新建会话，终端 cwd 为新的项目目录（不再静默回退到 HOME）
- [ ] 点击失效项目下 worktree 的既有修复流程（`handleWorkspaceClick`）不回归

### 3.5 删除 Worktree 时的分支处理（2026-08-10）

`git worktree remove` 不删分支 ref，所以删除确认框提供 opt-in 的「同时删除分支」。

1. 在某项目下创建 worktree（分支名 `wt-test`）
2. 点该 worktree 行的删除按钮

**验证点：**
- [ ] 确认框里「同时删除分支「wt-test」」复选框**默认未勾选**，下方有未合并提交会丢失的提示
- [ ] 不勾选删除 → 目录消失，再开「创建 Worktree」的基准分支下拉里 **`wt-test` 仍在**（预期行为）
- [ ] 勾选删除 → toast 提示「worktree 及分支已删除」，基准分支下拉里 `wt-test` **消失**，且可再用同名 `wt-test` 重新创建 worktree（不再报「分支已存在」）
- [ ] 当前正在使用（活跃）的 worktree 被删除时，左栏选中态清空，不留失效面板

- [ ] 可以正常输入命令（如 `ls`, `pwd`）
- [ ] 输出实时显示，无明显延迟
- [ ] 终端窗口大小自动适配面板

### 4.5a 终端自动重连（聚焦页面才重连，2026-09-14）

> 前置：设置里 tmux 失焦/空闲断连滑块保持默认（10/15 分钟）。自动重连只发生在页面可见时；页面隐藏期间零尝试，回来（切回标签 / 窗口聚焦 / 任意鼠标键盘活动）立即重连并重置退避节奏。

**A. 意外断开自愈（后端重启）**
1. 保持页面在前台，重启 dev 后端（`./dev.sh restart`）
2. 不做任何操作，观察终端

**验证点：**
- [ ] 断开后遮罩出现且带「正在自动重连…」提示
- [ ] 约 1s 内自动重连成功，遮罩自行消失，无需点击
- [ ] 后端持续不可用时：遮罩保留、提示不消失，退避间隔逐步拉长（≥30s 一次）；恢复后端后自动接上

**B. 失焦/空闲拆除后回归自愈**
1. 切到其他窗口（或最小化标签）超过设置的失焦断连时长（默认 10 分钟）
2. 切回来，观察终端；空闲断连（默认 15 分钟无输入）则在页面上动一下鼠标

**验证点：**
- [ ] 回来后无需点击「重连」，终端自动重建并接上（画面经补屏重放恢复）
- [ ] 桌面端自动重建不抢焦点：正在聊天面板输入时焦点不被终端拉走
- [ ] 手动「重连」按钮仍然可用且立即生效；重连期间遮罩按钮上方有「正在自动重连…」提示

### 4.6 pty 帧渲染视觉确认（cell_frame / runs 行编码）

> **适用范围**：pty 引擎会话（tmux 引擎是 raw 直通，不走服务端 grid 编码）。
> 可结构化断言的部分已由 `node scripts/pty-frame-regression.mjs`（17 项）覆盖，
> 本节只做**浏览器内的视觉确认** —— 字体、配色、光标形状、emoji 字形、宽字符
> 对齐、TUI 刷屏观感。改动 `src/engine/pty/` 的帧编码或 `useCellFrame.ts` 后
> 需过一遍（`docs/dev/plans/archive/2026-08-28-pty-frame-rle.md` §6）。
>
> 前置：按 §1.2 起服务，创建一个 **pty** 引擎会话（默认即是 pty），浏览器打开
> 前端（端口见 `.env.local` 的 `FRONTEND_PORT`）。下列命令整段粘进终端执行。

**V1 基础文本与颜色**

```bash
echo "Hello OmniTerm"
ls --color=always -la /usr/bin | head -30
printf '\x1b[1;31mBOLD RED\x1b[0m \x1b[4;34munderline blue\x1b[0m normal\n'
```

**验证点**
- [ ] 颜色、粗体、下划线范围准确，样式不越过行尾
- [ ] 序列结束后样式复位，后续提示符不是彩色

**V2 CJK / 全角对齐（宽字符占 2 列）**

```bash
printf '|中文|abc|\n'
printf '|abc|中文|\n'
printf '|12345|\n'
for i in $(seq 1 40); do echo "中文测试 $i ターミナル 滚动压测"; done
```

**验证点**
- [ ] 前两行的三根竖线**完全对齐**（中文按 2 列、ASCII 按 1 列）
- [ ] 第三行竖线比前两行靠前 2 列（符合宽度计算，非 bug）
- [ ] 全角/半角混排行没有字符重叠或半个字符

**V3 emoji（肤色修饰符 / ZWJ / 变体选择符）**

```bash
printf '👍 👍🏽 👨‍👩‍👧‍👦 ❤ ❤️ 🇨🇳 😀\n'
```

**验证点**
- [ ] `👍🏽` 是有肤色的竖拇指，不是「黄拇指 + 焦糖色方块」
- [ ] `❤️`（U+2764 + VS16）显示成彩色红心，不是黑白心形
- [ ] `👨‍👩‍👧‍👦` 合成一个家庭字形，不裂成四个头像
- [ ] 国旗与其余 emoji 等宽对齐

**V4 组合音标（零宽字符，`E-10` 专项）**

```bash
printf 'cafe\xcc\x81 na\xcc\x88ive A\xcc\x8a\n'
printf 'e\xcc\x81\xcc\x80\xcc\x81\n'
printf 'e\xcc\x81\ne\xcc\x81\n'
```

**验证点**
- [ ] `café` 的 é 是「e 上加锐音」的单个字形，不是 `e` 后跟一个孤立符号
- [ ] `ë`、`Å` 同理；多重组合符叠加在一格内，不占额外列
- [ ] 后两行渲染完全一致（组合符未被吞、未漂移）

**V5 行尾空格与背景色（RLE 不得截断尾部）**

```bash
printf '\x1b[41m%-40s\x1b[0m|END\n' 'selected'
printf 'AAA   \x1b[42m   \x1b[0mBBB\n'
```

**验证点**
- [ ] 第一行红底一直铺到第 40 列，`|END` 紧跟其后、没有被吞掉空格
- [ ] 第二行中段 3 个空格是绿底且可见，`BBB` 位置正确

**V6 快速输出不丢行 / 不撕裂**

```bash

```

**验证点**
- [ ] 数字连续无跳号、无整行错位
- [ ] 中断后画面停在某一帧，没有半行/错位残留

**V9 断线重连与多连接（`E-11` 专项）**

2. 会话**空闲 10 秒**（不输入任何内容）后刷新 → 重新点该会话
3. 再开一个标签页打开**同一个** pty 会话，一边跑 `top`，一边观察另一个标签页

**验证点**

- [ ] **空闲会话重连后立即出画面**（旧缺陷：ticker 懒初始化 + `select!` 挂起导致

- [ ] 两个标签页同时 attach 同一会话，两侧画面都正常刷新

**V10 升级后的旧资源缓存（已知取舍）**

cell_frame 只有 runs 一种行编码（旧的 `cells` 格式与 `hello.row_encoding` 协商
已移除）。前后端由同一产物发布，正常升级不会错配；仅当浏览器缓存住旧版前端

**验证点**
- [ ] 升级后若终端显示空白/空行 → 强制刷新（Ctrl+Shift+R）后恢复正常

**V11 上翻历史时新输出不冻结（绝对锚定 + 回底提示条）**

1. 跑 `top`，**在 top 运行期间**用滚轮向上翻几行（top 不进 alt-screen，滚轮会被接管）
2. 保持上翻状态不动，观察 10 秒
3. 敲 `q` 退出 top
4. 跑 `for i in $(seq 1 1500); do echo "中文测试 $i ターミナル 滚动压测"; done`，再上翻查看

**验证点**
- [ ] 上翻后右下角出现「↓ 下方有新输出」提示条
- [ ] 上翻期间窗口内容随输出推进（旧缺陷：永久停在上翻那一刻的快照，后续
      输出完全不可见，只有切换会话才恢复）
- [ ] 敲 `q`（任意按键）立即回到底部，提示条消失
- [ ] 点击提示条同样回底
- [ ] 空闲会话（无输出）上翻时不出现提示条、无额外请求
- [ ] 压测后再上翻，序号连续无跳号

**V12 周期性内容锚定（有状态锚，2026-09-12）**

> 与 V11 的差别：V11 压测行内容全唯一，指纹/位置机制都能过；本用例让锚点行
> 落在**重复内容**（空行/分隔线）上——此前六轮修复全部逃逸的场景（指纹重定位
> 在周期内容上必棘轮/滑移，见 `docs/dev/plans/2026-09-12-pty-viewport-stateful-anchor.md`）。

1. 跑周期性内容输出：`for i in $(seq 1 800); do echo; echo "────── 第 $i 段 ──────"; done`（空行 + 分隔线交替；或直接观察任一 Ink 系 agent 流式输出）
2. 输出进行中用滚轮上翻数屏，让窗口顶行停在**空行或分隔线**上
3. 保持不动观察 ≥10 秒（输出持续进行）

**验证点**
- [ ] 窗口内容不向 live 方向滑动、上滚位置不被吸回底部（旧缺陷：每 100ms 的保锚
      重拉被吸附到更新的重复内容副本，上滚进度瞬间被抹掉）
- [ ] 期间可继续向上滚动翻更早的内容，位置保持
- [ ] 敲任意键回底，提示条消失、恢复 live
- [ ] resize 窗口后再滚动正常（resize 清锚，刷新降级按偏移定位）
- [ ] 自动化判据：`node scripts/pty-viewport-anchor-regression.mjs`（五形态 × 8 轮，

## 12. ACP Chat 视图（Phase 4a）

> 前置：§11 至少创建过一个可用 agent；agent 的 `command` 指向一个可执行且能走通 ACP 协议的二进制（或 §11 异常场景里用于 500 测试的 placeholder）。

### 12.1 Layout 分发

| 步骤 | 预期 |
|------|------|
| 选中一个 `runtime_kind='tmux'` 的 session | 主面板渲染 xterm 终端，title bar 显示「terminal」 |
| 选中一个 `runtime_kind='acp'` 的 session | 主面板渲染 ChatView，title bar 显示「chat」+ 状态 chip（connecting / LIVE / disconnected / error） |
| 没有选中 session | ChatView 显示「请选择或创建一个 ACP 会话」占位 |
| 在 tmux 和 ACP session 间切换 | 每次都完整 remount（WS 生命周期重置，无残留连接） |
| 移动端（< 768px）在 terminal tab 选中 ACP session | MobileContent 也渲染 ChatView，与桌面一致 |

### 12.2 Prompt 与流式渲染

| 步骤 | 预期 |
|------|------|
| 输入文字 + Enter | WS 发送 `{"type":"prompt","text":"..."}`；消息列表追加一条 user bubble |
| Shift+Enter | textarea 换行，不发送 |
| 发送中（`sending=true`） | textarea 禁用；Send 按钮变成红色 Cancel 按钮 |
| 收到 `session_update`（AgentMessageChunk） | assistant 气泡追加文本，末尾有闪烁 caret |
| 收到 `prompt_done` | caret 消失；textarea 恢复可用；Send 按钮复位 |
| 收到 `prompt_error` | error banner 显示在 title bar 下方，红色背景 |
| 滚动到历史后收到新 chunk | 不强制滚到底（auto-stick 关闭）；手动滚到底后恢复 auto-stick |
| 自己发送时 | 自动 stick 到底部以看到自己的消息 |

### 12.3 异常场景

| 步骤 | 预期 |
|------|------|
| ACP session WS 连接失败（如后端未启动） | title bar chip 显示 error/disconnected；error banner 提示 |
| 发送 prompt 时未连接 | Send 按钮 disabled（`connectionState !== 'connected'`） |
| 发送中点 Cancel | WS 发送 `{"type":"cancel"}`；agent 应中断当前任务 |
| 切走 ACP session 再切回 | 消息历史保留（chatStore 按 session_id 索引，不在 unmount 时清空） |

### 12.4 上次输入卡片（跳转聚焦，2026-09-12）

> 消息区顶部居中的单行悬浮卡片（pixel-float 浮层，不占布局）：展示最近一次已送达的用户输入，点击跳回那个气泡。显隐按气泡相对视口位置三分：视口内、沉到视口下方（上翻进了更早历史）都收起，仅气泡升出视口顶缘（正在阅读其后的回复）时显示。

| 步骤 | 预期 |
|------|------|
| 会话已有至少一条已送达 user 消息 | 消息区顶部居中悬浮单行卡片，仅显示消息正文（无「上次输入」标签，多行压平空白） |
| 长消息 | 卡片最宽约占消息区 60%（移动端 88%），超出单行 ellipsis 截断；hover 出原生 tooltip 显示完整内容 |
| 目标气泡在视口内（用户正看着它） | 卡片收起 |
| 向下滚过这条消息、正在阅读其后的回复（气泡升出视口顶缘） | 卡片显示——作为「你最后问了什么」的参照 |
| 上翻越过这条消息、浏览更早历史（气泡沉到视口下方） | 卡片收起——多轮会话翻旧历史时不常驻 |
| 点击卡片 | 消息列表向上滚回该气泡、恰好落在卡片下方不被遮挡处，气泡出现 accent 描边 + ring 闪烁约 1.5s 后消退；随后气泡已在视口内，卡片自动收起 |
| 闪烁未消时滚开再点一次 | 闪烁动画重新播放（不是只滚动不动） |
| 最近一次输入是断连留痕气泡（undelivered，虚线框「未送达」） | 卡片显示的是再往前一条**已送达**的 user 消息；点击不跳到留痕气泡 |
| 刚发送新消息（auto-stick 在底部） | 新消息通常在视口内 → 不出现；回复流式变长把它顶出视口顶后出现 |
| 纯附件消息（无正文） | 卡片显示 `[附件]` 占位 |
| 会话尚无任何 user 消息（新会话） | 不渲染卡片 |
| hover / 按压卡片 | hover 底色 `--bg-elevated` → `--bg-surface`；按压 2px 硬阴影位移（§6 约定） |
| 极短会话内容不足一屏 | 气泡始终在视口内，卡片不出现 |

### 12.5 「回到底部」按钮（离底即显，2026-09-13）

> 消息区底缘居中的悬浮按钮（浮在输入区之上、不占布局）：离开底部即显示，滚回底部后消失——不要求尾部有新内容到达，流式输出与会话结束/空闲回看历史时都可用。

| 步骤 | 预期 |
|------|------|
| 贴底（自动跟随中，含内容不足一屏） | 不显示按钮 |
| 上翻离开底部（无论会话是否仍在流式输出） | 立即显示「↓ 回到底部」按钮，末条是否有新内容不影响显隐 |
| 会话结束/空闲（无任何新输出）时上翻 | 同样显示按钮 |
| 点击按钮 | 立即滚回底部并恢复自动跟随，按钮消失；此后新输出继续贴底跟随 |
| 手动滚回底部 | 按钮消失，流式输出继续贴底跟随 |

## 13. ACP 配置偏好持久化（2026-08-04）

> 前置：§11 创建过可用 agent；后端已应用 migration `20260804_acp_config_preferences.sql`。
> 底部配置栏（Mode/Model/Thinking/Config 选择器）只在 agent 下发 `config_options` 后可见，以下用例以可见为前提。

### 13.1 新建会话继承 agent 全局偏好

| 步骤 | 预期 |
|------|------|
| 在会话 A 的底部配置栏修改 Model（如从默认切到另一值） | 配置生效，配置栏显示新值 |
| 新建同一 agent 的会话 B | B 的底部配置自动显示会话 A 设置的 Model 值（agent 级偏好继承） |
| 在 B 中改回默认值 | B 生效；下次再建同 agent 会话 C 时按 B 的最终值继承 |

### 13.2 会话级覆盖优先

| 步骤 | 预期 |
|------|------|
| 在会话 A 设置 Model=X（此时 agent 全局偏好也是 X） | 两个表记录一致 |
| 在会话 A 把 Model 改成 Y | 仅会话 A 变 Y；agent 全局偏好仍 X |
| 新建会话 B | B 显示 X（agent 级） |
| 手动释放会话 A（release）后重新恢复（load_session） | A 显示 Y（会话级覆盖） |

### 13.3 进程生命周期内配置记忆

| 步骤 | 预期 |
|------|------|
| 修改配置后刷新浏览器（进程存活） | 刷新后配置栏仍显示上次值（`initial_config_notification` 回推缓存） |
| 手动 release 会话 → 重新进入会话 → 点「恢复会话」 | 重放期间配置栏短暂显示 agent 默认值，`ReplayEnd` 后切换为恢复值 |

### 13.4 删除清理

| 步骤 | 预期 |
|------|------|
| 删除一个 ACP 会话 | `session_config_options` 对应行被清理（或 FK 级联） |
| 删除一个项目 | 项目下全部会话的 `session_config_options` 被清理 |
| 删除一个 agent（无会话引用时） | `agent_config_preferences` 对应行被清理 |

### 13.5 边界与降级

| 步骤 | 预期 |
|------|------|
| agent 侧移除某配置项后恢复会话 | 该项被跳过、不报错，其余项正常恢复 |
| agent 不返回 `config_options`（如 opencode 部分路径） | restore 自动跳过（缓存空无法过滤），会话正常建立，配置栏可能为空（已知能力边界） |
| 恢复期间 agent 响应慢/失败 | 单项目 warn 跳过，10s 超时兜底，不阻塞会话建立/恢复 |

### 13.6 发送即自动恢复（进程已释放）

| 步骤 | 预期 |
|------|------|
| ACP 会话空闲 5 分钟被 reaper 自动回收（或手动 release）后，直接输入并发送消息 | 无需点「恢复会话」，后端自动 spawn agent + 历史重放，稍后 agent 正常回复；期间不出现 Internal error |
| 恢复过程中「已释放」指示（DEAD badge / 恢复按钮） | 保持稳定不闪断（3s 轮询不覆盖），发送后恢复成功自动转为 LIVE |
| 释放后不发送、只点「恢复会话」 | 仍走手动恢复流程（与自动恢复共用同一后端逻辑） |
| 释放后刷新浏览器（WS 重连，进程不在 supervisor） | 会话显示「已释放」而非「已结束」，输入可用；发送消息自动恢复，不再强制先点恢复 |
| 删除会话后刷新浏览器 | 仍标记「已结束」（DB 行不存在 → `session_not_found`） |

### 13.7 已结束会话的配置快照置灰展示（2026-09-13）

> 前置：后端已应用 migration `20260913_add_config_options_snapshot.sql`；agent 会下发 `config_options`（配置栏可见）。

| 步骤 | 预期 |
|------|------|
| 在活跃会话 A 观察底部配置栏样式（记为基准） | 正常亮度，可点开下拉 |
| 让 A 被 reaper 回收或手动 release → **刷新浏览器** → 重新进入 A | 配置栏仍显示最后已知配置，样式与活跃一致但整体置灰（opacity 0.5）；下拉按钮 disabled，点击无反应、不弹选项列表 |
| 已结束会话的置灰配置栏 hover | 出现 tooltip「Session ended — showing last known config」 |
| 在已结束的 A 中发送任意消息触发自动恢复 | 配置栏自动解除置灰恢复可交互，值随后端恢复的配置帧刷新（restore_config_prefs 写回用户偏好） |
| 活跃会话刷新浏览器（进程存活） | 配置栏显示快照值但**不置灰**（`agentLive=true`），随后被 live/replay 配置帧接管 |
| agent 从未下发过配置的会话被回收后进入 | 配置栏不出现（快照为空，维持旧行为，不出现空置灰条） |
| 已知限制：会话在页面打开期间被回收（不刷新） | 配置栏保持上次活跃态显示（与改动前行为一致，属既有缺口，需刷新后走快照置灰） |

### 15.7 工作时长（结算 + 流式实时，2026-09-02）

> 前置：需可用 agent（见 §11）。口径与实现约束见 `docs/dev/plans/archive/2026-08-30-acp-work-time.md`（E8/E10/E11/E12）。

| 步骤 | 预期 |
|------|------|
| 发送 prompt，agent 尚未吐第一帧 | 只见底部乱码流一行，**无**计时器（气泡还不存在，没有「气泡底部」可放） |
| 气泡出现后观察 | 底部元信息行显示 `工作中 N秒`，每秒 +1，数字不等宽抖动（`tabular-nums`） |
| 计时器与乱码流同屏 | 两者各占一行、互不交叠；消息列无横向滚动条 |
| turn 中途弹审批 banner 且不应答 | 计时器**冻住不跳**（对齐后端 `work_ms = 墙钟 − 等真人`）；应答后从冻结值续跳 |
| 并发两个审批只批掉一个 | 计时器仍冻住（队列见底才恢复） |
| turn 正常定稿 | 同一槽位换成 `已工作 M秒`（M ≈ 最后一次的 N，不出现两个数字并排），颜色更淡一档 |
| turn 出错 / 点取消 / 会话结束 | 计时器立即消失，不留一个永不落定的数字 |
| 流式期间刷新页面再接回同一会话 | 计时器从**非 0** 值起显（锚点取在建行 `created_at`；该值是首次 flush 建行时刻，偏小属预期） |
| 两个 ACP 会话同时跑 turn | 各自计时独立，不串号（切会话不拆 WS，计时按 sessionId 分列） |
| hover 计时器 | tooltip 提示「本地实时估算，定稿以后端结算为准」 |

## 16. 双引擎会话（pty 引擎 Phase 4）

> 前置：后端 + 前端就绪。pty 与 tmux 长期共存：创建会话时可选引擎，pty 为默认。

### 16.1 创建会话引擎选择器

| 步骤 | 预期 |
|------|------|
| 点 worktree「创建会话」 | 弹窗含「会话引擎」单选组：pty（默认选中）/ tmux，各带一句话差异说明 |

### 16.2 pty 会话交互

| 步骤 | 预期 |
|------|------|
| pty 会话内拖选文本 | 直接选中并自动复制（无需 Shift），toast 提示 |

| 重启后端后回到会话 | 会话自动重建（最后 cwd），回放重启前输出 |

### 16.3 tmux 会话回归（冻结行为不变）

| 步骤 | 预期 |
|------|------|
| tmux 会话滚轮上滚 | 走 copy-mode（与改动前一致）；Shift 拖选复制正常 |
| modern 键位 Ctrl+Shift+→/↓/Q/X | 仍注入 prefix 组合（分屏/新窗/关 pane） |
| 外部会话区块 | tmux 可用时照常展示与收养 |
| 重启后端 | tmux 会话幸存（tmux server），行为不变 |

## 17. ACP 聊天附件（「+」抽屉，2026-09-10）

> 前置：可用 agent（§11）。设计决策见 `docs/dev/plans/archive/2026-09-10-chat-file-attachments.md`。

### 17.1 入口与抽屉形态

| 步骤 | 预期 |
|------|------|
| 打开 ACP 会话（agent 支持图片或文件能力） | 输入框内右侧、发送按钮左出现「+」方形按钮（与 Send 同高） |
| agent 两种能力都未声明 | 不渲染「+」（能力帧到达前同样不渲染，连上后出现） |
| 点「+」（移动端视口 <768px） | 抽屉从底部滑出、贴 MobileNav 上方；点外部或 Esc 关闭；再点「+」可收起 |
| 点「+」（桌面） | 浮层锚定「+」上方，不超出视口；Esc / 点外部关闭 |
| 打开时输入框有草稿/软键盘展开 | 点「+」后软键盘收起（textarea 失焦），抽屉不被键盘遮挡 |

### 17.2 相册卡片（图片）

| 步骤 | 预期 |
|------|------|
| 点「相册」 | 关闭抽屉并唤起系统图片选择器（移动端为相册/拍照选项） |
| 选择 1~N 张图片 | 输入框上方出现缩略图（56×56），可逐个 ✕ 移除、可叠加多次选择 |
| 无文字直接点发送 | 消息发出（纯附件合法），气泡显示缩略图 |
| agent 未声明图片能力 | 「相册」卡片置灰、副文案说明「当前 agent 不支持图片输入」，点击无反应 |

### 17.3 文件卡片（任意文件）

| 步骤 | 预期 |
|------|------|
| 点「文件」 | 关闭抽屉并唤起系统文件选择器（不限类型） |
| 选择一个 PDF/md/zip | 输入框上方出现文件 chip（图标 + 文件名 + 大小），可 ✕ 移除 |
| 无文字直接发送 | 消息发出；气泡显示文件名 chip（含大小） |
| 刷新页面后回到该会话 | 历史里文件 chip 仍在（只落元数据，内容不回看属预期） |
| agent 未声明 embeddedContext | 「文件」卡片置灰、副文案说明；若绕过前端直连 WS 发送则收到明确拒绝错误 |

### 17.4 边界

| 步骤 | 预期 |
|------|------|
| 带附件时 agent 正在跑（sending） | 「排队」按钮置灰（队列槽只接受纯文本）；直接发送仍可用（等 idle） |
| 选择 >9MiB 的文件发送 | 后端回 `message_too_large` 可读错误（管道口径，不做前端预检） |
| 同一文件连续选两次 | 两次都能触发（input value 每次清空） |
| 切换会话 | 附件清空，不串到另一个会话 |

## 18. Sidebar 会话上下文菜单与批量操作（2026-09-10）

> 设计决策见 `docs/dev/plans/archive/2026-09-10-sidebar-session-context-menu.md`。

### 18.1 上下文菜单入口

| 步骤 | 预期 |
|------|------|
| 桌面：在会话行上点鼠标右键 | 浏览器默认菜单不出现；弹出 omniterm 风格浮层菜单，含「批量操作」「重命名」两项（图标 + 文字） |
| 桌面：右键靠近视口右缘/下缘的行 | 菜单被 clamp 进视口，不溢出 |
| 桌面：点击菜单外任意处 / 按 Esc | 菜单关闭 |
| 移动端：按住会话行 ≥0.5s | 菜单在触点位置弹出（有轻微振动反馈） |
| 移动端：长按后松开手指 | 仅弹菜单，**不会**同时激活该会话（补发 click 被抑制） |
| 移动端：按住后滑动列表 | 不触发长按（滚动保护） |
| 移动端：长按会话名文字 | 不弹出系统文本选择菜单 |
| 点菜单「重命名」 | 打开重命名会话弹窗，改名后列表更新；行内已无铅笔按钮 |
| 归档区块 / 外部会话区块的行 | 无右键/长按菜单（只读区块，符合预期） |

### 18.2 批量操作：选择模式

| 步骤 | 预期 |
|------|------|
| 点菜单「批量操作」 | 进入选择模式：该会话被预选、行首出现勾选框，底部状态栏替换为操作栏（「已选 1 个」+ 归档/释放/删除/✕） |
| 点击其他会话行 | 切换勾选、计数更新；**不**切换当前会话视图 |
| 点击 worktree 行 / 项目行 | 照常展开折叠 / 激活 workspace，不影响勾选 |
| 勾选多个项目的会话 | 计数累计（可跨项目选择） |
| 选择模式下右键会话行 | 不弹菜单（避免重置选择集） |
| 点操作栏 ✕ | 退出选择模式、清空勾选，底部状态栏恢复连接状态 |

### 18.3 批量归档 / 释放进程 / 删除

| 步骤 | 预期 |
|------|------|
| 全选终端会话 | 「归档」「释放」按钮禁用（灰、不可点），「删除」可用 |
| 混选终端 + ACP 会话后点「归档」 | 弹窗确认，正文第二行提示「其中 N 个终端会话不支持该操作，将被跳过」 |
| 确认归档 | 仅 ACP 会话被归档（终端行保留），「已归档」区块出现这些会话，选择模式退出 |
| 勾选驻留中的 ACP 会话点「释放」 | 弹窗确认；确认后进程释放（行内 A 徽标变灰）；若释放的是当前会话，ChatView 显示「恢复会话」 |
| 点「删除」 | destructive 红色确认按钮；确认后选中会话全部删除 |
| 勾选当前正在查看的会话执行任一操作 | 操作后主视图切回空态，无残留请求错误 |
| 执行过程中按 Esc / 点弹窗外 | 弹窗不关闭（防误触），直到执行完成 |
| 操作完成后 | 列表刷新、选择模式退出；归档操作同步「已归档」区块 |
