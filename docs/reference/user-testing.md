## 1. 环境准备

### 1.1 系统依赖

| 依赖 | 最低版本 | 用途 |
|------|---------|------|
| Rust | 1.87+ | 后端编译 |
| Node.js | 22+ | 前端构建 |
| pnpm | 10+ | 前端包管理 |
| tmux | 3.3+ | 终端会话管理 |
| SQLite | 3.35+ | 数据存储 |

### 1.2 启动开发环境

**一键启动（推荐）：**

```bash
cd /home/pax/coding/OmniTerm

./dev.sh start     # 启动后端 + 前端
./dev.sh stop      # 停止所有服务
./dev.sh restart   # 重启
./dev.sh status    # 查看运行状态
./dev.sh logs      # 实时日志（Ctrl+C 退出）
./dev.sh logs be   # 仅后端日志
./dev.sh logs fe   # 仅前端日志
```

启动成功后输出：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  后端 API:  http://localhost:9777
  前端 UI:   http://localhost:9778
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> 后端仅监听 127.0.0.1（通过 Vite proxy 访问），前端监听 0.0.0.0（局域网可访问）。

**手动启动：**

```bash
# 终端 1：后端
cd /home/pax/coding/OmniTerm
. "$HOME/.cargo/env"
cargo run
# → Listening on 0.0.0.0:9777

# 终端 2：前端
cd frontend
pnpm dev
# → Vite dev server on http://localhost:9778 (proxies /api → :9777)
```

### 1.3 验证服务

```bash
curl http://localhost:9777/api/v1/health
# 期望：{"status":"ok"}
```

## 3. 工作区管理

### 3.1 创建工作区

1. 点击侧边栏顶部 **+** 按钮
2. 输入工作区名称（如 `Home`）
3. 输入根路径（如 `/home/pax`）
4. 确认

**验证点：**
- [ ] 工作区出现在侧边栏列表中
- [ ] 显示名称和根路径
- [ ] 空名称被拒绝
- [ ] 不存在的路径被拒绝（后端校验）

### 3.2 切换工作区

- 点击工作区名称展开/折叠
- 选中的工作区高亮显示
- 文件管理器自动加载该工作区根目录

**验证点：**
- [ ] 点击切换展开状态
- [ ] 文件管理器内容随工作区切换更新
- [ ] 终端区域不受影响

### 3.3 删除工作区

（当前 UI 未暴露删除按钮，通过 API 测试）

```bash
curl -X DELETE http://localhost:9777/api/v1/workspaces/{id}
```

### 3.4 项目路径失效检测与修复（2026-08-08）

项目真实目录被移动/改名/删除后，Sidebar 应标记失效并提供重新定位入口。

**验证点：**
- [ ] 正常项目路径无任何失效标记
- [ ] `mv` 项目目录到别处后，切走再切回浏览器标签页（触发 `visibilitychange` 刷新），项目行路径**变红**并显示 **⚠ 修复按钮**，tooltip 提示「项目路径不存在」
- [ ] 点击 ⚠ 打开「项目路径失效」修复对话框，显示原失效路径
- [ ] 浏览/输入新路径后点「更新路径」，对话框关闭、项目恢复，路径不再标红
- [ ] 修复后在新项目路径下新建会话，终端 cwd 为新的项目目录（不再静默回退到 HOME）
- [ ] 点击失效项目下 worktree 的既有修复流程（`handleWorkspaceClick`）不回归

### 3.5 删除 Worktree 时的分支处理（2026-08-10）

`git worktree remove` 不删分支 ref，所以删除确认框提供 opt-in 的「同时删除分支」。

1. 在某项目下创建 worktree（分支名 `wt-test`）
2. 点该 worktree 行的删除按钮

**验证点：**
- [ ] 确认框里「同时删除分支「wt-test」」复选框**默认未勾选**，下方有未合并提交会丢失的提示
- [ ] 不勾选删除 → 目录消失，再开「创建 Worktree」的基准分支下拉里 **`wt-test` 仍在**（预期行为）
- [ ] 勾选删除 → toast 提示「worktree 及分支已删除」，基准分支下拉里 `wt-test` **消失**，且可再用同名 `wt-test` 重新创建 worktree（不再报「分支已存在」）
- [ ] 当前正在使用（活跃）的 worktree 被删除时，左栏选中态清空，不留失效面板

### 4.2 连接终端

1. 点击一个会话
2. 终端区域建立 WebSocket 连接
3. 显示 `[attached to session-name]` 绿色提示
4. 出现 shell 提示符

**验证点：**
- [ ] 连接成功显示绿色提示
- [ ] 可以正常输入命令（如 `ls`, `pwd`）
- [ ] 输出实时显示，无明显延迟
- [ ] 终端窗口大小自动适配面板
- [ ] 拖拽调整面板宽度后终端自动重新适配

### 4.3 终端基本操作

在终端中执行以下操作：

```bash
# 基本命令
echo "Hello OmniTerm"
ls -la
cat /etc/hostname

# 交互式命令
top        # 按 q 退出
vim        # 正常编辑，:q 退出
htop       # 如果已安装

# 长输出
find / -name "*.conf" 2>/dev/null | head -50
```

**验证点：**
- [ ] 命令输出正确
- [ ] 交互式程序（vim/htop）正常工作
- [ ] 颜色输出正确渲染
- [ ] 长输出可滚动查看
- [ ] Ctrl+C 中断正常工作

### 4.4 多会话

1. 创建第二个会话
2. 在两个会话之间切换
3. 每个会话保持独立状态

**验证点：**
- [ ] 切换会话后终端内容保持
- [ ] 返回原会话时状态完整
- [ ] 不同会话可以运行不同程序

### 4.5 断开与重连

1. 刷新浏览器页面
2. 重新点击同一会话

**验证点：**
- [ ] 显示 `[disconnected]` 红色提示

## 7. 移动端

### 7.1 响应式布局

将浏览器窗口缩小到 768px 以下，或使用手机访问。

**验证点：**
- [ ] 自动切换到移动端布局
- [ ] 底部出现 Tab 导航栏：终端 | 文件 | 会话 | 设置
- [ ] 三栏布局变为单栏全屏
- [ ] Tab 切换内容正常

### 7.2 中文输入法（IME）

在移动端或桌面端使用中文输入法：

1. 在终端中切换到中文输入法
2. 输入拼音，观察候选词
3. 选择候选词上屏

**验证点：**
- [ ] IME 组合过程中不发送中间按键
- [ ] 最终文字正确发送到终端
- [ ] 不会中断 IME 候选词选择

### 7.3 手势交互（2026-07-30 移动端交互优化）

在真机或 DevTools 触摸模拟下测试：

1. **终端触摸滚动**：在终端区域竖向拖动，tmux 内容随手指滚动（进入 copy-mode 滚动历史）；横向拖动则触发 xterm 文本选择
2. **跟手滑动切 tab**：在内容区横向拖动，内容跟随手指位移；越界（第一页往右/最后一页往左）有阻尼
3. **滑动提交切 tab**：拖动超过阈值后松手，切换到相邻 tab 并伴随触觉反馈；未过阈值则回弹
4. **状态栏滑切会话**：在顶部状态栏横向快速滑动，切换到上/下一个会话
5. **横屏键盘隐藏 KeyBar**：横屏 + 软键盘弹出时 MobileKeyBar 自动隐藏，收起键盘后恢复
6. **长按粘贴**：长按终端区域 500ms 弹出粘贴菜单，点击 Paste 将剪贴板文本写入终端

**验证点：**
- [ ] 竖向拖动滚动 tmux 历史，横向拖动选择文本，两者不互相干扰
- [ ] tab 滑动跟手、越界阻尼、松手提交或回弹均符合预期
- [ ] 状态栏横滑循环切换会话（仅 1 个会话时无动作）
- [ ] 横屏 + 键盘弹出时 KeyBar 隐藏
- [ ] 长按弹出粘贴菜单，粘贴成功；移动超过 10px 或松手取消长按

> 前置：后端 `cargo check` 通过、前端 `npx tsc -b` 通过。Phase 3 后端 + 前端 UI 就绪；完整 ACP 协议联调需要配置一个能跑起来的 agent 可执行文件（如本地编译的 `agent-client-protocol` 示例）。

## 12. ACP Chat 视图（Phase 4a）

> 前置：§11 至少创建过一个可用 agent；agent 的 `command` 指向一个可执行且能走通 ACP 协议的二进制（或 §11 异常场景里用于 500 测试的 placeholder）。

### 12.1 Layout 分发

| 步骤 | 预期 |
|------|------|
| 选中一个 `runtime_kind='tmux'` 的 session | 主面板渲染 xterm 终端，title bar 显示「terminal」 |
| 选中一个 `runtime_kind='acp'` 的 session | 主面板渲染 ChatView，title bar 显示「chat」+ 状态 chip（connecting / LIVE / disconnected / error） |
| 没有选中 session | ChatView 显示「请选择或创建一个 ACP 会话」占位 |
| 在 tmux 和 ACP session 间切换 | 每次都完整 remount（WS 生命周期重置，无残留连接） |
| 移动端（< 768px）在 terminal tab 选中 ACP session | MobileContent 也渲染 ChatView，与桌面一致 |

### 12.2 Prompt 与流式渲染

| 步骤 | 预期 |
|------|------|
| 输入文字 + Enter | WS 发送 `{"type":"prompt","text":"..."}`；消息列表追加一条 user bubble |
| Shift+Enter | textarea 换行，不发送 |
| 发送中（`sending=true`） | textarea 禁用；Send 按钮变成红色 Cancel 按钮 |
| 收到 `session_update`（AgentMessageChunk） | assistant 气泡追加文本，末尾有闪烁 caret |
| 收到 `prompt_done` | caret 消失；textarea 恢复可用；Send 按钮复位 |
| 收到 `prompt_error` | error banner 显示在 title bar 下方，红色背景 |
| 滚动到历史后收到新 chunk | 不强制滚到底（auto-stick 关闭）；手动滚到底后恢复 auto-stick |
| 自己发送时 | 自动 stick 到底部以看到自己的消息 |

### 12.3 异常场景

| 步骤 | 预期 |
|------|------|
| ACP session WS 连接失败（如后端未启动） | title bar chip 显示 error/disconnected；error banner 提示 |
| 发送 prompt 时未连接 | Send 按钮 disabled（`connectionState !== 'connected'`） |
| 发送中点 Cancel | WS 发送 `{"type":"cancel"}`；agent 应中断当前任务 |
| 切走 ACP session 再切回 | 消息历史保留（chatStore 按 session_id 索引，不在 unmount 时清空） |

## 13. ACP 配置偏好持久化（2026-08-04）

> 前置：§11 创建过可用 agent；后端已应用 migration `20260804_acp_config_preferences.sql`。
> 底部配置栏（Mode/Model/Thinking/Config 选择器）只在 agent 下发 `config_options` 后可见，以下用例以可见为前提。

### 13.1 新建会话继承 agent 全局偏好

| 步骤 | 预期 |
|------|------|
| 在会话 A 的底部配置栏修改 Model（如从默认切到另一值） | 配置生效，配置栏显示新值 |
| 新建同一 agent 的会话 B | B 的底部配置自动显示会话 A 设置的 Model 值（agent 级偏好继承） |
| 在 B 中改回默认值 | B 生效；下次再建同 agent 会话 C 时按 B 的最终值继承 |

### 13.2 会话级覆盖优先

| 步骤 | 预期 |
|------|------|
| 在会话 A 设置 Model=X（此时 agent 全局偏好也是 X） | 两个表记录一致 |
| 在会话 A 把 Model 改成 Y | 仅会话 A 变 Y；agent 全局偏好仍 X |
| 新建会话 B | B 显示 X（agent 级） |
| 手动释放会话 A（release）后重新恢复（load_session） | A 显示 Y（会话级覆盖） |

### 13.3 进程生命周期内配置记忆

| 步骤 | 预期 |
|------|------|
| 修改配置后刷新浏览器（进程存活） | 刷新后配置栏仍显示上次值（`initial_config_notification` 回推缓存） |
| 手动 release 会话 → 重新进入会话 → 点「恢复会话」 | 重放期间配置栏短暂显示 agent 默认值，`ReplayEnd` 后切换为恢复值 |

### 13.4 删除清理

| 步骤 | 预期 |
|------|------|
| 删除一个 ACP 会话 | `session_config_options` 对应行被清理（或 FK 级联） |
| 删除一个项目 | 项目下全部会话的 `session_config_options` 被清理 |
| 删除一个 agent（无会话引用时） | `agent_config_preferences` 对应行被清理 |

### 13.5 边界与降级

| 步骤 | 预期 |
|------|------|
| agent 侧移除某配置项后恢复会话 | 该项被跳过、不报错，其余项正常恢复 |
| agent 不返回 `config_options`（如 opencode 部分路径） | restore 自动跳过（缓存空无法过滤），会话正常建立，配置栏可能为空（已知能力边界） |
| 恢复期间 agent 响应慢/失败 | 单项目 warn 跳过，10s 超时兜底，不阻塞会话建立/恢复 |

### 13.6 发送即自动恢复（进程已释放）

| 步骤 | 预期 |
|------|------|
| ACP 会话空闲 5 分钟被 reaper 自动回收（或手动 release）后，直接输入并发送消息 | 无需点「恢复会话」，后端自动 spawn agent + 历史重放，稍后 agent 正常回复；期间不出现 Internal error |
| 恢复过程中「已释放」指示（DEAD badge / 恢复按钮） | 保持稳定不闪断（3s 轮询不覆盖），发送后恢复成功自动转为 LIVE |
| 释放后不发送、只点「恢复会话」 | 仍走手动恢复流程（与自动恢复共用同一后端逻辑） |
| 释放后刷新浏览器（WS 重连，进程不在 supervisor） | 会话显示「已释放」而非「已结束」，输入可用；发送消息自动恢复，不再强制先点恢复 |
| 删除会话后刷新浏览器 | 仍标记「已结束」（DB 行不存在 → `session_not_found`） |

## 14. 自动断连/释放超时设置（2026-08-05）

> 前置：后端 `cargo check` 通过、前端 `npx tsc -b` 通过。ACP 相关用例需一个可用的 agent（见 §11）；tmux 用例需 tmux 会话。入口：设置 → 会话 三个分钟滑块（ACP 空闲回收 / 失焦断连 / 空闲断连，值域 1..60）。

### 14.1 ACP 空闲回收超时

| 步骤 | 预期 |
|------|------|
| 将「ACP 空闲回收」调至 1 分钟 | 滑块显示 1；刷新页面后仍为 1（后端 settings 表持久化） |
| 让一个 ACP 会话静默待命（无进行中 prompt、无未决权限）超过设置值 | reaper 自动回收，Sidebar 显示「已释放」，`ps` 可见 agent 子进程消失 |
| 同一阈值内有进行中 prompt 的会话 | 不被回收（活跃判定排除） |
| 调为 5 分钟后重启后端，再打开设置 | 滑块显示 5（DB 记录优先于默认值） |

### 14.2 tmux 失焦/空闲断连超时

| 步骤 | 预期 |
|------|------|
| 将「失焦断连」调至 1 分钟，聚焦 tmux 会话后切换标签页/窗口（失焦） | 约 1 分钟后终端显示断连覆盖层；切回立即自动重连（`[attached]`） |
| 将「空闲断连」调至 1 分钟，聚焦会话后停止任何操作 | 约 1 分钟后显示断连覆盖层；重新按键/移动鼠标后重连 |
| 刷新页面 | 两个滑块保持用户设置（localStorage `omniterm_blur_disconnect_min` / `omniterm_idle_disconnect_min`） |

### 14.3 内存占用警告

| 步骤 | 预期 |
|------|------|
| 任一滑块拖到 ≥30 分钟 | 滑块下方显示内存占用警告文案 |
| 拖回 30 分钟 | 警告仍显示（阈值含 30） |
| 拖回 <30 分钟 | 警告消失 |

## 15. 聊天气泡动作体系（2026-08-13）

> 前置：需可用 agent（见 §11）。覆盖 `docs/dev/plans/archive/2026-08-11-chat-bubble-actions.md` 的 P0/P1 验收点。

### 15.1 桌面 hover 动作条

| 步骤 | 预期 |
|------|------|
| 桌面端 hover 任意 user 气泡 | 气泡下方淡入动作条（复制 / 引用 / 编辑），移出隐藏 |
| hover 最后一条 assistant 气泡 | 动作条含复制 / 引用 / 复制为 Markdown / 重新生成 |
| hover 历史中间 assistant 气泡 | 动作条**不含**重新生成 |
| Tab 聚焦到动作条按钮 | `:focus-within` 下动作条保持可见（键盘可达） |
| 流式渲染期间 hover assistant 气泡 | 动作条不出现（避免复制半截内容） |

### 15.2 复制正文

| 步骤 | 预期 |
|------|------|
| 复制 user 消息 | 剪贴板内容 = 该消息纯文本；toast「消息已复制」 |
| 复制含 thought/tool 卡的 assistant 消息 | 剪贴板 = 所有 text 块拼接（`\n\n`），不含思考/工具日志 |
| 裸 http（非 localhost）访问 | 复制仍成功（D1 兜底路径）——必须实测 |
| 剪贴板 API 被拒（无权限） | toast 显示复制失败，不静默 |

### 15.3 引用到输入框

| 步骤 | 预期 |
|------|------|
| 点「引用」 | 输入框出现 `> 引用内容` 且光标在末尾，可直接追加追问 |
| 引用含多段 text 的 assistant 消息 | 每段以 `> ` 前缀分行 |
| 点完引用后切到另一会话再切回 | 引用不串到别的会话草稿 |
| 引用后发送 | 输入框清空，引用块作为 prompt 发出 |

### 15.4 编辑重发 / 重新生成（回归）

| 步骤 | 预期 |
|------|------|
| user 气泡点「编辑」 | 原消息保留、进入编辑态；提交后原消息标「已编辑」，编辑稿作为新 prompt 发出 |
| 最后一条 assistant 点「重新生成」 | 最后一条 user prompt 重发，assistant 回复追加不替换 |
| 会话已结束/未连接 | user 气泡编辑、assistant 重新生成按钮不显示（复制/引用仍可用） |

### 15.5 块级复制与复制为 Markdown

| 步骤 | 预期 |
|------|------|
| hover 正文块右上角 | 显示复制角标；点击复制该块原文 |
| hover thinking 块 | 复制角标在「thinking」行；复制思考原文 |
| hover 工具卡片 | 复制角标复制 tool_call 的 `content`（diff 类复制原文） |
| 复制为 Markdown | 剪贴板为 `## Agent: …` + `## Turn: …` + 正文 + `### 工具调用` 摘要 |

### 15.6 移动端长按菜单

| 步骤 | 预期 |
|------|------|
| 移动端长按消息 label/空白区 500ms | 弹出浮动菜单（复制/引用/…），`hapticTap` 震动 |
| 长按后拖动 >10px | 菜单不弹出（取消） |
| 长按正文（text 气泡） | 不弹动作菜单，系统文本选择正常（iOS 无双菜单） |
| 菜单不超出视口 | 靠近屏幕右缘时左移，不溢出 |
