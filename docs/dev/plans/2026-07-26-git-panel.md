## 1. 功能范围（v1 = B 档核心工作流）

**包含**：
- status 变更文件列表（staged / unstaged 双区，含 untracked、conflicted 标记）
- 文件级 diff 查看（unified 视图）
- log 历史（分页列表 50 条/页，点击 commit 经 `git show` 看详情）
- stage / unstage（文件级）
- commit（多行 message 输入）
- discard 文件（唯一不可逆操作，强制二次确认弹窗）
- 分支：列表 + 切换 + 创建（`checkout -b`，从当前 HEAD）
- push / pull / fetch（首次 push 自动 `--set-upstream`）

**明确排除**（终端里做更合适 / 复杂度不成比例）：
- hunk 级 stage/unstage/discard
- stash、merge/rebase 冲突处理 UI、历史图（graph）、cherry-pick/reset
- 分支删除/重命名、远程分支操作、force push
- amend、commit+push 组合、AI 生成 commit message
- Git 身份多 profile 管理、GitHub PR 集成

产品定位依据：OmniTerm 是终端-first，面板价值是"不打断终端工作流的快速查看 + 提交"，复杂操作留给中间的终端。

## 2. ADR

### ADR-1 后端用 CLI 子进程，不引入 git2/libgit2

沿用 `src/git/mod.rs` 既有的 `tokio::process::Command` 调 git CLI 模式。零 native 依赖、错误信息与 CLI 一致；openchamber（simple-git = 同样 shell 出 git）验证了可行性。分层：`src/api/git.rs`（handler）+ `src/git/`（service），符合现有 API 组织。

### ADR-2 仓库绑定 = 跟随活动 session 的 workspace

取活动 session 的 workspace 路径，后端 `git rev-parse --show-toplevel` 解析仓库根；切 session 自动切仓库，非 git 目录显示空态。否决项：跟随 FileManager 浏览路径（FM 翻子目录导致面板闪变）、独立仓库选择器（多余 UI 实体，违反奥卡姆剃刀）。

**安全约束**：API 不接受任意路径参数，只接受 session/workspace id，仓库路径由后端解析，防任意目录 git 操作。

### ADR-3 diff = 自研 unified patch 渲染，后端返回 `git diff` 原文

否决 `@codemirror/merge`：它消费新旧两份完整文档、在客户端重算 diff——与 `git diff`（即实际将被 stage/commit 的内容）可能不一致，属语义级缺陷；且绑架后端 API 形状（传全量内容而非 patch）。自研方案：unified diff 格式是冻结标准，解析器 ~60 行，纯展示层 bug 后果可控，像素风样式完全掌控。窄栏（240px~半屏）只做 unified 单栏视图。v1 不做语法高亮。

**翻盘条件**（已确认不成立）：若近期计划 hunk 级操作，`unifiedMergeView` 的 chunk accept/reject 有先发优势——用户确认无此计划。

### ADR-4 刷新 = 统一可见时串行轮询 + 事件提示层（不按 session 类型分叉）

- **保底**：GIT tab 可见时串行轮询 `git status --porcelain --no-optional-locks`（上次完成后 5s 调度下一次，非固定 interval）；tab 隐藏/面板折叠即停。`--no-optional-locks` 避免与用户终端 git 操作竞争 `index.lock`。
- **叠加**：面板自身操作后立即刷新；手动刷新按钮；ACP edit 类 tool_call 完成时前端触发立即刷新（`chatStore` 已解析 tool kind，零后端改动）。
- **不按 tmux/ACP 类型分叉策略**，理由（AGENTS.md §8）：① ACP 事件非完备信号源——`fs/write_text_file` 和 ACP terminal 是协议可选路径，agent 可直接写磁盘/自己 spawn `git commit`，收不到任何事件；② 仓库被多 session 共享（一个 ACP + 一个 tmux 指向同一 workspace），刷新策略绑 session 类型隐含"仓库只被这一个 session 改"的错误假设；③ 分叉收益仅是省每 5s 一次 <50ms 只读子进程。事件是加速器，不是替代品。
- diff/log/branches 不轮询，按需拉取。
- 否决项：`/files/watch` SSE（忽略 `.git`，感知不到 index/HEAD 变化）；新建 git 专用推送通道（违反奥卡姆剃刀）。

### ADR-5 UI = 新建 RightPanel 容器组件

容器持有：tab 状态（appStore `rightPanelTab: 'files' | 'git'`，localStorage 持久化）、统一 `.panel-title-bar`（tab 嵌入，遵循 ui-style-guide §12：VT323 14px UPPERCASE、en/zh 同写英文值）、折叠态 40px 竖条。FileManager 退化为纯内容组件（title bar 与折叠渲染上移）。两面板保持挂载、display 切换（保留 FM 导航状态；GIT tab 不可见 = 轮询停止）。移动端 `files` tab 渲染容器，FILES | GIT 免费复用。否决项：塞进 FileManager.tsx 内部（1060 行继续膨胀、耦合语义错误）、双 title bar（违反 §4）。

### ADR-6 交互安全默认值

- 脏工作区切分支被 git 拒绝时如实展示报错，**不做自动 stash**（隐式魔法难排查）。
- push/pull/fetch 带 `GIT_TERMINAL_PROMPT=0` + 超时；需交互认证时明确报错提示"请在终端操作"，绝不挂起。
- git stderr 提炼为用户可读错误文案（参考 openchamber `parseGitErrorText` 思路）。

### ADR-7 GitPanel 内部布局 = 二级视图切换 + diff 底部抽屉

顶部一行常驻：分支选择器 + fetch/pull/push 按钮。其下 CHANGES | HISTORY 二级切换：CHANGES = staged/unstaged 变更列表 + 底部固定 commit 输入框；HISTORY = log 分页列表。diff 查看复用 FileManager 既有的底部抽屉交互（FileDrawer 同款，点文件从底部滑出）。否决项：同屏堆叠（窄栏互相挤压、滚动嵌套）；内嵌 diff（窄栏展不开，且抽屉是用户已熟悉的模式）。

## 3. Glossary

| 术语 | 定义 |
|------|------|
| RightPanel | 右侧栏容器组件，持有 FILES/GIT tab 状态、title bar、折叠态；FileManager 与 GitPanel 的父级 |
| GitPanel | GIT tab 的内容组件，含变更列表/commit 区/分支/历史 |
| 仓库绑定（repo binding） | GIT 面板当前操作的仓库 = 活动 session 的 workspace 经 `rev-parse --show-toplevel` 解析出的仓库根 |
| 可见时轮询（visible polling） | 仅 GIT tab 可见且面板未折叠时进行的串行 status 轮询 |
| 刷新提示（refresh hint) | 非保底的立即刷新触发源：面板自身 mutation、手动按钮、ACP edit tool_call 完成事件 |
| 双区（staged/unstaged） | status 列表按 index 状态与 working tree 状态分两区展示，同一文件可同时出现在两区 |
| unified patch 渲染 | 前端直接解析 `git diff` 的 unified 格式文本逐行渲染，不在客户端重算 diff |
| 二级视图（CHANGES / HISTORY） | GitPanel 内部的子切换：变更工作区视图与历史列表视图互斥展示 |
| diff 抽屉 | 复用 FileDrawer 交互模式的底部滑出面板，用于展示单文件 diff 或 commit 详情 |

## 4. openchamber 踩坑借鉴清单（实施时对照）

1. staged/unstaged 双 scope 建模：同一文件可同时在两区，staged 行请求 diff 需带 staged 标志（`git diff --cached`）。
2. stage/unstage 快速连点会竞争 `index.lock`——前端 mutation 串行队列（或至少禁用按钮直到上一操作返回）。
3. 大 diff 防御：超大文件 diff 截断展示（提示"过大，请在终端查看"）。
4. push/pull 错误文案提炼（auth 失败、non-fast-forward、no upstream 是三大高频）。
